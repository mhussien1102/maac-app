# MAAC — Accounting & Auditing (برنامج واحد: أدمن + مستخدم)

تطبيق ويب عربي (RTL) بـ **HTML + CSS + JavaScript** بس، من غير أي framework وغير أي build.
فيه **صفحة دخول واحدة** للتطبيق كله، والإيميل هو اللي بيحدد هتفتح لك أنهي صفحات:

| الإيميل اللي دخلته | اللي بيفتح |
| --- | --- |
| إيميل أدمن (`admin@maac.com`) + الباسورد الصح | **صفحات الأدمن** → `admin/` |
| إيميل مستخدم مسجّل (`user@maac.com` أو أي حساب اتعمل بالتسجيل) | **صفحات المستخدم** → `app/` |
| إيميل جديد مالوش حساب | رسالة «مفيش حساب بالإيميل ده» + زر **إنشاء حساب جديد** بنفس الإيميل → كود تأكيد (OTP) → **صفحات المستخدم** |

## تشغيل المشروع

الموديولات (`type="module"`) مبتشتغلش من `file://`، فلازم سيرفر محلي:

```bash
cd maac-app
python3 -m http.server 8000      # أو: npx serve .
# افتح http://localhost:8000
```

لو فتحت الصفحة بالضغط المزدوج على الملف هتظهر رسالة تنبيه بتقول كده.

## الحسابات التجريبية

| الدور | الإيميل | الباسورد |
| --- | --- | --- |
| أدمن | `admin@maac.com` | `Admin@123` |
| مستخدم | `user@maac.com` | `User@123` |

على صفحة الدخول فيه صندوق بزرارين «استخدمه» بيملا الحقول لك.
كود التأكيد (OTP) في وضع التجربة بيظهر على الشاشة في صندوق فيه زر «اكتبه».
للدفع التجريبي: كارت ناجح `4111 1111 1111 1111`، وكارت مرفوض `4000 0000 0000 0002`.

## هيكل المشروع

```

├─ login.html  signup.html  verify.html  forgot.html  reset.html     صفحات مشتركة (للزائر فقط)
├─ app/                  منطقة المستخدم   (role = user)
│  ├─ index.html  chat.html  upload.html  payment.html
├─ admin/                منطقة الأدمن     (role = admin)
│  ├─ index.html  chat.html  upload.html  subscriptions.html
└─ assets/
   ├─ css/   base → components → layout → pages  (tokens + ثيم فاتح/داكن)
   ├─ fonts/ IBM Plex Sans Arabic + Amiri (محلية)
   └─ js/
      ├─ boot.js          سكربت عادي (مش module): الثيم قبل الرسم + حارس المسارات
      ├─ core/            routes, storage, html, validators, icons, …
      ├─ data/            بيانات تجريبية (seeds)
```

## إزاي بيشتغل التوجيه حسب الدور

1. `auth.service.js` بيفتح الجلسة بعد الدخول وبيخزّن فيها `role` = `admin` أو `user`.
2. كل صفحة HTML عليها `data-auth` و`data-area`:
   - `data-auth="guest"` → صفحات الدخول والتسجيل (لو أنت داخل بالفعل بتتحوّل لصفحتك الرئيسية).
   - `data-auth="required" data-area="user|admin"` → صفحات المنطقتين.
   - `data-auth="entry"` → `index.html` بس.
3. `boot.js` بيقرأ الجلسة **قبل ما الصفحة تترسم** وبيحوّل:
   - مفيش جلسة → `login.html?next=…`
   - أدمن بيفتح `app/…` → يتحوّل لـ `admin/index.html`
   - مستخدم بيفتح `admin/…` → يتحوّل لـ `app/index.html`
4. `authService.requireAuth(area)` بيعمل نفس الفحص تاني من جوه الـ JS (طبقة تانية).
5. `?next=` بيتقبل **بس** لو الصفحة جوه منطقة نفس الدور (مفيش open redirect، ومفيش قفز بين المنطقتين).

### قواعد الإيميلات
- إيميلات الأدمن **محجوزة**: مينفعش حد يسجّل بيها، ومفيش كود استرجاع لها (الرد شكله زي أي إيميل مش موجود، علشان محدش يعرف مين الأدمن).
- أي إيميل مش أدمن ومالوش حساب → يتوجّه للتسجيل (مش بيفتح له حاجة من غير تأكيد الإيميل).
- حساب المستخدم الجديد بيتفتح بعد تأكيد الكود، وبيبدأ بمحادثات وملفات فاضية — كل شخص ليه بياناته (`conversations:<id>` و`files:<id>`).

## صفحة اشتراكات الأدمن

متوصّلة بالحسابات الحقيقية في التطبيق:
- كل مستخدم أكّد إيميله بيظهر في الجدول: **في انتظار الدفع** (لسه مدفعش) ← **دفع** ← **منتهي** (اشتراكه خلص).
- لما مستخدم يدفع، الجدول وكروت الإحصائيات عند الأدمن بتتحدّث لحظيًا (حدث `storage` على `maac:accounts`).
- فيه 4 صفوف عينة (علامة «بيانات تجريبية») علشان الجدول ميبقاش فاضي أثناء التجربة. لإخفائها:
  `assets/js/data/subscriptions.seed.js` ← `SHOW_SAMPLE_SUBSCRIBERS = false`.

## إضافة أدمن جديد

في `assets/js/data/users.seed.js` أضف عنصر لـ `ADMIN_USERS`:

```js
{ id: 'u-admin-2', email: 'hala@maac.com', password: 'Strong@Pass1', name: 'هالة', title: 'Admin' }
```

## التخزين المحلي (localStorage / sessionStorage)

كل المفاتيح بتبدأ بـ `maac:` — أهمها: `maac:session` (الجلسة)، `maac:theme`، `maac:accounts`، `maac:conversations:<id>`، `maac:files:<id>`.
«تذكّرني على الجهاز ده» = جلسة 30 يوم في `localStorage`، من غيرها = 12 ساعة في `sessionStorage`.

## ⚠️ مهم قبل الإنتاج (Production)

الشغل الحالي **واجهة فقط ببيانات تجريبية**، والتحقق من الدور بيتم في المتصفح — وده للتجربة وتسهيل الاستخدام مش للأمان:

- بيانات الأدمن (الإيميل والباسورد) موجودة في كود الواجهة لأغراض العرض. في الإنتاج لازم تتحقق منها على **السيرفر** وتتشال من الـ JS.
- لازم السيرفر هو اللي يصدر الجلسة (Cookie `HttpOnly` أو JWT فيه `role`) ويفرض صلاحيات الأدمن على كل API (مثلًا `GET /api/admin/subscriptions` للأدمن بس) — أي فحص في المتصفح ممكن يتعدّل.
- الدفع الحالي محاكاة؛ اربطه ببوابة دفع حقيقية (Stripe / Paymob / …) ولا تستقبل بيانات الكارت بنفسك.
- كود التأكيد (OTP) لازم يتولّد ويتبعت من السيرفر (إيميل / SMS) — العرض الحالي على الشاشة للتجربة بس.

### إزاي تبدّل الـ mock بـ API حقيقي
كل التعامل مع البيانات في `assets/js/services/*.js` وصفحات الواجهة بتنادي عليها بس. استبدل جسم الدوال (`login`, `register`, `verifyOtp`, `snapshot`, `charge`, …) بـ `fetch` لسيرفرك وسيب أسماء الدوال وشكل النتائج زي ما هي، وباقي الواجهة هتفضل شغالة.
